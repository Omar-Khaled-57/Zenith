# Zenith deployment

## Build commands

| Command | Source | Result |
| --- | --- | --- |
| `npm run build` | [`package.json`](../package.json) | Runs `tsc && vite build`; frontend output goes to `dist/`. |
| `cargo build --release --manifest-path src-tauri/worker/Cargo.toml` | [`README.md`](../README.md) | Builds the sensor worker for local development. |
| `npm run tauri build` | [`README.md`](../README.md) | Full desktop build and bundle. |

[`tauri.conf.json`](../src-tauri/tauri.conf.json) wires the full build:
`beforeBuildCommand` is `npm run build && cargo build --release --manifest-path
src-tauri/worker/Cargo.toml`, and `frontendDist` is `../dist`. The dev hook
(`beforeDevCommand`) runs the same worker build followed by `npm run dev`.

The working tree contains `Zenith_1.0.0_x64_en-US.msi` and
`Zenith_1.0.0_x64-setup.exe` in `dev/release/1.0.0/`. The 1.1.0 release notes
name equivalent 1.1.0 installer files, but no 1.1.0 installer binaries are
present in the tree. `dev/` is excluded by `.gitignore`, so these are local
release materials rather than tracked build outputs.

## Targets and prerequisites

- `bundle.targets` is `all` in `tauri.conf.json`; no target list is narrowed
  further.
- The README targets Windows 10/11 and notes WebView2 is bundled with the OS.
  Real temperatures on Windows require the PawnIO driver
  (`winget install namazso.PawnIO`) and an elevated run.
- Platform-specific bundle resource maps exist for Windows and Linux. The
  Linux worker reads hwmon; the macOS worker backend is a placeholder that
  reports the driver as unavailable.
- iOS and Android icon assets exist under `src-tauri/icons/`, but no mobile
  target configuration was found in the Tauri config files.

## What is not configured

- No CI/CD workflow, release pipeline, or deployment manifest for Zenith was
  found. Workflows under `dev/lhm` and `dev/pawnio-modules` belong to ignored
  vendored reference repositories.
- No code-signing, notarization, auto-update, or package publishing
  configuration was found in the project configuration files.
- No deployment-specific environment variables are declared; see
  [configuration](./configuration.md).
